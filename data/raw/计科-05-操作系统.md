# 操作系统

> 合成讲义 · 仅供 RAG 系统测试使用 · 学科:操作系统

## 一、操作系统概述

### 1.1 定义

操作系统(OS)是管理计算机硬件与软件资源、为用户和应用程序提供接口与服务的系统软件。

### 1.2 功能

- **进程管理**(CPU 调度)
- **内存管理**
- **文件管理**
- **设备管理**
- **用户接口**(命令行、图形界面)

### 1.3 分类

- **批处理系统**:作业成批处理,无交互
- **分时系统**:多用户通过终端同时使用,时间片轮转
- **实时系统**:对响应时间有严格要求的系统(硬实时/软实时)
- **网络操作系统**:为网络提供共享资源管理
- **分布式操作系统**:管理多台计算机协同工作

## 二、进程管理

### 2.1 进程的概念

**进程**:程序在某数据集合上的一次动态执行过程,是系统进行资源分配和调度的基本单位。

**进程 vs 程序**:
- 程序是静态的指令集合,进程是动态的执行实体
- 一个程序可对应多个进程(多开)
- 一个进程可包含多个程序

### 2.2 进程的状态

```
   创建
    ↓
   就绪 ←──→ 运行 → 阻塞
              ↓
            终止
```

- **就绪(Ready)**:已获得所需资源,等待 CPU
- **运行(Running)**:正在 CPU 上执行
- **阻塞(Blocked)**:等待某事件(如 I/O 完成)而暂停
- **创建(New)**:进程刚被创建
- **终止(Terminated)**:进程执行结束

### 2.3 进程控制块(PCB)

PCB 是进程存在的唯一标志,包含:
- 进程标识符(PID)
- 进程状态
- 程序计数器
- CPU 寄存器
- 内存管理信息
- I/O 状态信息

### 2.4 进程的同步与互斥

**临界资源**:一段时间内只允许一个进程使用的资源。
**临界区**:访问临界资源的代码段。

**同步原则**:
1. **空闲让进**:临界区空闲时,应允许请求进程进入
2. **忙则等待**:临界区被占用时,其他请求应等待
3. **有限等待**:请求应在有限时间内进入临界区
4. **让权等待**:进不了临界区应释放 CPU

### 2.5 信号量

由 Dijkstra 提出,包含一个整数和两个原子操作(P、V)。

```python
class Semaphore:
    def __init__(self, value): self.value = value
    def P(self):  # wait
        while self.value <= 0: pass
        self.value -= 1
    def V(self):  # signal
        self.value += 1
```

**互斥信号量**:初值 1,实现互斥访问临界资源。
**同步信号量**:初值 0,实现进程间先后顺序。

## 三、CPU 调度

### 3.1 调度层次

- **高级调度**(作业调度):从外存作业调入内存
- **中级调度**(内存调度):将挂起进程换出/换入内存
- **低级调度**(进程调度):从就绪队列选进程上 CPU

### 3.2 调度算法

**(1) 先来先服务(FCFS)**:按到达顺序调度。非抢占。简单但平均周转时间长。

**(2) 短作业优先(SJF)**:选运行时间最短的作业。平均周转时间最优,但长作业可能饥饿(需要知道运行时间)。

**(3) 优先级调度**:选优先级最高的进程。可能造成低优先级饥饿。

**(4) 时间片轮转(RR)**:每个进程轮流运行一个时间片,适合分时系统。

**(5) 多级反馈队列**:多个就绪队列,优先级递减,时间片递增。新进程先到高优先级,运行完一个时间片未完成则降级。

### 3.3 死锁

**定义**:多个进程相互等待对方持有的资源而无限等待。

**四个必要条件**:
1. **互斥**:资源一次只被一个进程使用
2. **请求和保持**:进程已获得的资源不释放又请求新资源
3. **不剥夺**:资源只能由进程主动释放
4. **循环等待**:存在进程-资源的循环链

**处理策略**:
- **预防**:破坏任一必要条件
- **避免**:银行家算法
- **检测与恢复**:检测死锁后强制剥夺资源
- **忽略**:鸵鸟策略(大多数 OS 选择)

## 四、内存管理

### 4.1 连续分配

**单一连续分配**:只支持单道程序,简单但浪费内存。

**固定分区分配**:内存划分为若干固定大小分区,每个分区装一道程序。会产生内部碎片。

**动态分区分配**:根据进程大小动态分配。会产生外部碎片。可用**首次适应**、**最佳适应**、**最坏适应**等算法。

### 4.2 分页存储

**页**:进程的逻辑地址空间划分为等大小的页。
**页框(块)**:物理内存划分为等大小的块(与页大小相同)。
**页表**:记录每个页对应的物理块号,实现逻辑地址到物理地址的映射。

**地址结构**:逻辑地址 = 页号 + 页内偏移
- 页号 = 逻辑地址 / 页面大小
- 页内偏移 = 逻辑地址 % 页面大小

**特点**:无外部碎片,有少量内部碎片(最后一页)。

### 4.3 分段存储

按程序的逻辑结构(代码段、数据段、栈段)划分。每个段大小不等,有自己的段号和段内偏移。

**优点**:便于共享和保护(对整个段操作);**缺点**:有外部碎片。

### 4.4 段页式存储

先分段,每段再分页。结合段式与页式的优点。

### 4.5 虚拟内存

**思想**:程序不需要全部装入内存即可运行,需要时再调入。

**理论基础**:
- **时间局部性**:刚被访问的存储单元很可能很快再被访问
- **空间局部性**:刚被访问的存储单元附近单元很可能被访问

**页面置换算法**:
- **最佳置换(OPT)**:淘汰最久不被访问的(不可实现,作为基准)
- **先进先出(FIFO)**:淘汰最早进入内存的页
- **最近最久未使用(LRU)**:淘汰最久未被使用的页
- **时钟(CLOCK)**:循环扫描,使用位为 0 的页被淘汰

**缺页率**:缺页次数 / 总访问次数。置换算法影响缺页率。

## 五、文件系统

### 5.1 文件的逻辑结构

- **无结构文件**(流式文件):字节序列
- **有结构文件**(记录式文件):由记录组成,记录有定长/变长

### 5.2 文件的物理结构

- **连续分配**:文件占用连续磁盘块,顺序访问快,但有外部碎片,不便扩展
- **链接分配**:磁盘块用指针串联,无碎片但只支持顺序访问
- **索引分配**:为每个文件建立索引块,支持随机访问

### 5.3 目录结构

- **单级目录**:所有文件在一个目录下,不能重名
- **两级目录**:主文件目录(MFD)+用户文件目录(UFD)
- **多级目录**(树形):现代 OS 采用
- **无环图目录**:文件可被多个目录共享

## 六、设备管理

### 6.1 I/O 控制方式

- **程序直接控制**:CPU 忙等,效率低
- **中断驱动**:I/O 完成后中断 CPU,CPU 处理
- **DMA**:直接内存访问,适合块设备
- **通道**:独立处理 I/O,CPU 只需发命令

### 6.2 缓冲管理

设置缓冲区缓和 CPU 与 I/O 设备速度差:
- **单缓冲**:一块缓冲区
- **双缓冲**:两块交替使用
- **循环缓冲**:多个缓冲区组成循环队列

## 七、典型例题

**例 1**:有 5 个进程 P1, P2, P3, P4, P5,几乎同时到达,预计运行时间分别为 10, 1, 2, 1, 5。用 SJF 调度,求平均周转时间。

解:按运行时间排序(短作业优先):P2(1), P4(1), P3(2), P5(5), P1(10)。
完成时间:P2=1, P4=2, P3=4, P5=9, P1=19。
周转时间=完成时间-到达时间(几乎同时到达,约 0):1, 2, 4, 9, 19。
平均周转时间 = (1+2+4+9+19)/5 = 35/5 = 7。

**例 2**:某系统采用分页存储,页面大小为 4 KB。已知逻辑地址 0x3245,求页号与页内偏移。

解:4 KB = 4096 B = 2^12 B,所以页内偏移占低 12 位。
逻辑地址 0x3245 = 0011 0010 0100 0101₂
页内偏移:0x245 = 581
页号:0x3 = 3

**例 3**:用银行家算法判断某状态是否安全。

状态:5 个进程 P0-P4,3 类资源 A(10), B(5), C(7)。当前分配和需求如下表所示,问该状态是否安全?

| 进程 | 已分配(A,B,C) | 最大需求(A,B,C) |
|------|---------------|-----------------|
| P0 | (0,1,0) | (7,5,3) |
| P1 | (2,0,0) | (3,2,2) |
| P2 | (3,0,2) | (9,0,2) |
| P3 | (2,1,1) | (2,2,2) |
| P4 | (0,0,2) | (4,3,3) |

剩余资源:(10-7, 5-2, 7-5) = (3,3,2)。
从 P1 开始:可满足 (2,2,2) ≤ (3,3,2),执行 P1,资源回收 → (3+2, 3+0, 2+0) = (5,3,2)。
然后 P3:可满足 (2,2,2) ≤ (5,3,2),执行 → (5+2, 3+1, 2+1) = (7,4,3)。
然后 P0:可满足 (7,5,3) ≤ (7,4,3)? 不满足。
然后 P2:可满足 (9,0,2) ≤ (7,4,3)? 不满足。
然后 P4:可满足 (4,3,3) ≤ (7,4,3)? 不满足。

由于 P0, P2, P4 都不能在新状态下执行,该状态**不安全**。
