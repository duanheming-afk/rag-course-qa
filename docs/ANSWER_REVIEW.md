# 模型答案人工评分

本流程评价评测报告中的模型回答，和 `review_holdout.py` 对题目、参考答案的审核是两件事。自动关键词分、文件引用率和向量相似度不能代替人工判定。

## 启动

在项目根目录、配置好虚拟环境后执行：

```powershell
.\.venv\Scripts\python.exe scripts/review_answers.py
```

默认读取 `reports/holdout_runs` 中最新的 `answers.json`，网页地址为 `http://127.0.0.1:7862/`。不需要启动 Ollama 或重新构建 Qdrant 索引；页面读取的是已记录的答案和检索快照。

指定某次评测或只导出当前风险/评分汇总：

```powershell
.\.venv\Scripts\python.exe scripts/review_answers.py --report reports/holdout_runs/20260921T061907988848Z/answers.json
.\.venv\Scripts\python.exe scripts/review_answers.py --export-only
```

已有人工评分会自动恢复，不会重新置零。Linux/macOS 激活虚拟环境后，将解释器路径换为 `python`。只运行一个评分进程；暂不支持多进程、多评分者独立打分和裁决工作流。

## 逐题操作

1. 先阅读问题、原文与已有参考答案；参考答案也可能标注不当，不能当绝对标准。
2. 再看模型最终答案，核对正确性和是否覆盖问题要求。不要求模型机械复述参考答案的所有内容。
3. 对照每个引用编号的实际片段，确认它真的支持相应结论。语义相似不是逻辑蕴含。
4. 查看被筛选前的回答和警告，判断删除结论是否导致关键内容缺失。
5. 完成四项评分、填写评分者。存在低分时必须记录分类和理由，再点击“保存本题评分”。
6. 点击“下一条未评分”继续；该按钮不会保存未提交的修改。
7. 完成一批后点击“导出当前汇总”。为了完整报告效果，应覆盖全部题型，而不是只评风险高的题。

## 评分尺度

| 项目 | 0 | 1 | 2 |
|---|---|---|---|
| 正确性 | 错误、未完成或行为不符合要求 | 部分正确 | 核心结论和条件正确；应拒答/澄清时行为正确 |
| 完整性 | 没有覆盖要求 | 只覆盖部分要点 | 覆盖问题真正要求的要点 |
| 证据支持 | 关键结论没有依据 | 部分结论有依据 | 关键结论均有原文依据 |
| 引用支持 | 引用错误或缺失 | 部分引用支持 | 每条引用支持相应结论 |

只有完全正确的拒答/澄清题，证据支持和引用支持可选 `N/A`。可回答题不能以 `N/A` 跳过证据检查。所有评分默认“未评分”，工具不会自动替人填写。

## 自动风险不等于真实失败

风险排序依据：请求异常、预期行为不符、目标文件召回/引用缺失、结论删除、字面关键词未命中、关键词疑似章节标题。它们只用于筛选先核对的样本。

例如 h004 的参考关键词包含“2 方法”，模型回答提到 SMOTE 但没有复述该标题，字面指标得到 0。这提示应核对关键词标注，不能直接把该题判错。工具保留原始题目、标签和代理分，不自行“修正”以提高指标。

## 保存位置与可复现性

默认输出到 `reports/manual_review_local/<评测运行ID>/`：

- `reviews.json`：人工四项评分、问题分类、评分者、UTC 时间、来源 SHA256、修订号和历史记录；首次保存才创建。
- `review_summary.json` / `review_summary.md`：每个策略、每类题目的已评分数量、分母和完全正确比例；证据/引用只计算适用项。
- `automatic_diagnostics.md`：自动风险清单，不包含人工判错结论。

原始 `answers.json`、`manual_review.json` 和评测标签不被覆盖。来源报告发生变化时工具拒绝沿用旧评分；请为新评测选择新目录。当前 `data/raw` 原文可能已经变化，历史证据以报告中的检索快照为准。

评分文件可能包含姓名和个人备注，因此本地输出目录已加入 `.gitignore`，不自动发布到 GitHub。公开效果报告前应检查脱敏，不能直接公开整个评分文件。

## 汇报口径

“完全正确比例”是已评分题目中正确性得 2 的比例，不是四项均分，也不是关键词命中率。未评分不会按零分处理；只有部分样本时，同时展示覆盖率并声明选择偏差，不能把子集比例写成全部 136 题的准确率。

对于全部样本完成的评测，报告仍应说明资料性质、题型分布、模型与配置、人工评分者数量，以及是否采用双人独立标注。单人自建集复核不是独立双盲评测。

先记录真实错误，再根据检索遗漏、生成遗漏、引用不支持、公式/条件错误或标注问题分别改进；修改后使用新运行重新评测，保留修改前后报告和评分来源。
